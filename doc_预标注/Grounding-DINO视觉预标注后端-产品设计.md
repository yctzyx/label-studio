# Grounding DINO 视觉预标注产品设计

## 1. 产品定位

Grounding DINO 视觉预标注是 Label Studio 二开平台中的图片目标检测预标注能力模块。它不是一个示例 ML Backend，而是面向项目管理员、标注员、质检员和平台运维的完整产品功能。

产品核心价值：

- 让用户通过标注模板中的业务标签自动生成检测提示词。
- 在数据管理页批量生成目标框预测，降低冷启动标注成本。
- 在标注页提供交互式检测能力，辅助标注员快速框选目标。
- 沉淀项目级提示词、阈值、模型版本和质量指标，形成可复用的视觉预标注配置。

与现有大模型预标注的关系：

- `label-studio-llm-backend` 负责文本、多模态理解、结构化结果生成。
- `label-studio-grounding-dino-backend` 负责图片开放词表目标检测，输出 `RectangleLabels`。
- 平台层统一管理不同预标注服务，按项目任务类型选择合适能力。

## 2. 产品目标

### 近期目标

- 将 Grounding DINO 从官方示例升级为独立、可部署、可配置、可观测的视觉预标注后端。
- 在 Label Studio 项目设置中提供完整的“视觉预标注”配置入口。
- 实现标注模板、业务标签、提示词和预测结果的稳定联动。
- 支持批量预测和标注页交互式预测两个主流程。

### 中期目标

- 提供预标注质量统计，包括接受率、删除率、修改率、平均置信度、预测耗时。
- 支持项目级 Prompt 模板库和标签别名管理。
- 支持多模型版本切换，例如 Swin-T、Swin-B，以及后续 GroundingDINO + SAM。

### 非目标

- 不在本阶段训练项目专属检测模型。
- 不替代人工质检流程。
- 不把所有视觉能力都塞进一个后端，分割、OCR、属性抽取后续以模型编排方式接入。

## 3. 用户角色

### 项目管理员

负责创建项目、配置标注模板、启用视觉预标注、调节阈值、发起批量预测。

核心诉求：

- 不写代码即可完成模型连接。
- 能看懂标签和提示词之间的映射。
- 能测试配置是否能跑通。
- 能控制预标注结果偏召回还是偏精度。

### 标注员

负责在标注页查看候选框、调整框位置、删除误检、补充漏检。

核心诉求：

- 预测框要能直接落在正确业务标签上。
- 交互式预标注要快，失败时原因清楚。
- 不需要理解模型参数。

### 质检员

负责评估预标注质量，判断是否适合批量启用。

核心诉求：

- 看到每类标签的预测质量。
- 识别误检高、漏检高的标签。
- 对比不同阈值和 Prompt 配置的效果。

### 平台运维/算法工程师

负责部署后端、管理 GPU、模型权重、日志、监控和版本升级。

核心诉求：

- 后端独立部署，环境和 Label Studio 解耦。
- 模型版本、权重、GPU 使用可控。
- 出问题时能定位是图片拉取、模型推理、配置错误还是服务异常。

## 4. 核心概念

### 业务标签

业务标签来自 Label Studio 标注模板中的 `RectangleLabels`。

示例：

```xml
<RectangleLabels name="label" toName="image">
  <Label value="人员" predicted_values="person,people,human"/>
  <Label value="安全帽" predicted_values="helmet,hard hat"/>
  <Label value="车辆" predicted_values="vehicle,car,truck"/>
</RectangleLabels>
```

### 检测提示词

Grounding DINO 使用英文自然语言短语进行开放词表检测。平台应从业务标签自动生成提示词：

```text
person, helmet, vehicle
```

生成优先级：

1. 标签级 Prompt 覆盖值。
2. `predicted_values` 的第一个值。
3. 标签英文名。
4. 通过内置词典或翻译服务把中文标签转换为英文。
5. 无法转换时提示管理员补充别名。

### 标签映射

模型返回 phrase 后，需要映射回业务标签。

映射优先级：

1. 与标签级 Prompt 精确匹配。
2. 与 `predicted_values` 任一别名匹配。
3. 与标签名大小写匹配。
4. 模糊匹配或包含匹配。
5. 仍失败时进入“未映射结果”策略。

未映射结果策略：

- 默认不输出，避免污染标注结果。
- 可配置为输出到“待确认”标签。
- 可配置为输出到第一个标签，仅用于调试，不建议生产开启。

### 阈值

Grounding DINO 有两个关键阈值：

- `box_threshold`：框置信度阈值，越高越保守。
- `text_threshold`：文本匹配阈值，越高越严格。

产品上应提供三档预设：

- 高召回：`box=0.20`，`text=0.20`
- 均衡：`box=0.30`，`text=0.25`
- 高精度：`box=0.45`，`text=0.35`

## 5. 信息架构

项目设置中新增一级页面：

```text
项目设置
  -> 预标注
    -> 大模型预标注
    -> 视觉预标注
```

“视觉预标注”页面包含 6 个区块：

- 服务连接
- 模型配置
- 标签与提示词映射
- 推理参数
- 预测策略
- 测试与质量统计

## 6. 项目设置页设计

### 6.1 服务连接

字段：

- 启用视觉预标注：开关。
- 服务地址：默认 `http://localhost:9092`。
- 认证方式：无认证 / Basic Auth / Token。
- Label Studio 回连地址：用于后端拉取受保护图片。
- API Token：用于后端访问 Label Studio 文件。

操作：

- 测试连接。
- 查看健康状态。
- 查看模型设备：CPU / CUDA。
- 查看模型权重和配置。

状态：

- 未连接：提示填写服务地址。
- 连接成功：显示健康、模型版本、设备、响应时间。
- 连接失败：展示错误分类，例如网络不可达、认证失败、模型未加载。

### 6.2 模型配置

字段：

- 模型类型：Grounding DINO。
- 模型版本：Swin-T / Swin-B。
- 权重文件：默认权重 / 自定义权重。
- 推理设备：自动 / CPU / CUDA。
- 最大并发：默认 1。

规则：

- GPU 模式默认建议单 worker。
- 切换模型版本需要重启后端或触发模型重载。
- CPU 模式显示性能提示，不建议大批量生产使用。

### 6.3 标签与提示词映射

核心表格：

| 业务标签 | 标签颜色 | 检测词 | 别名 | 状态 |
| --- | --- | --- | --- | --- |
| 人员 | 蓝色 | person | people, human | 可用 |
| 安全帽 | 橙色 | helmet | hard hat | 可用 |
| 车辆 | 绿色 | vehicle | car, truck | 可用 |

功能：

- 自动读取当前标注模板中的 `RectangleLabels`。
- 自动读取 `<Label predicted_values="...">`。
- 支持在 UI 中编辑检测词和别名。
- 支持一键同步回标注模板的 `predicted_values`。
- 支持检测词为空的标签高亮提示。
- 支持忽略某个标签，不参与预标注。

设计原则：

- 业务标签是用户认知中心。
- Prompt 是业务标签的模型表达，不要求普通用户直接写长 prompt。
- 允许高级用户查看最终生成的完整 prompt。

### 6.4 推理参数

字段：

- 参数模式：高召回 / 均衡 / 高精度 / 自定义。
- Box Threshold。
- Text Threshold。
- 单图最大框数。
- 每标签最大框数。
- 是否过滤小框。
- 最小框面积比例。
- 是否过滤边缘框。

交互：

- 切换预设时自动填充阈值。
- 自定义后显示为“自定义”模式。
- 参数旁提供简短解释。

### 6.5 预测策略

字段：

- 批量预测默认策略：覆盖旧预测 / 保留旧预测 / 仅为空任务预测。
- 标注页交互策略：模板 Prompt / 手动 Prompt / 模板 + 手动追加。
- 未映射结果策略：丢弃 / 输出到待确认 / 调试输出。
- 结果写入方式：预测结果 / 草稿 / 自动提交为标注。

建议默认值：

- 批量预测：仅为空任务预测。
- 标注页交互：模板 Prompt，可手动覆盖。
- 未映射结果：丢弃。
- 写入方式：预测结果。

### 6.6 测试与质量统计

测试功能：

- 选择一张项目图片。
- 点击“测试预标注”。
- 展示候选框预览。
- 展示生成的 prompt、耗时、框数量、平均分。
- 支持调节阈值后重新测试。

质量统计：

- 总预测任务数。
- 总预测框数。
- 用户接受框数。
- 用户删除框数。
- 用户修改框数。
- 接受率。
- 删除率。
- 平均预测耗时。
- 按标签统计质量。

## 7. 标注页设计

### 默认模式

标注员进入任务后，看到模型生成的候选框。

候选框应具备：

- 正确业务标签。
- 置信度。
- 原始检测 phrase。
- 来源标识：Grounding DINO。

标注员操作：

- 接受框。
- 拖拽调整。
- 删除误检。
- 新增漏检。

### 交互式预标注

在标注页提供“视觉预标注”面板。

控件：

- 检测目标：默认来自模板，可切换为手动输入。
- 标签选择：勾选本次要检测的业务标签。
- 参数预设：高召回 / 均衡 / 高精度。
- 运行按钮。

运行后：

- 新结果作为候选预测插入。
- 不直接覆盖用户已确认标注。
- 可选择清除上一次模型预测。

### 错误反馈

常见错误应转成用户能理解的提示：

- 图片无法读取：检查 Label Studio 地址和 Token。
- 没有可用检测词：请在视觉预标注设置中补充标签别名。
- 服务未连接：请检查视觉预标注服务地址。
- GPU 显存不足：请降低并发或切换模型。

## 8. 数据管理页设计

在数据管理页保留 Label Studio 原有“获取预测”能力，同时增强提示：

- 显示当前启用的视觉预标注服务。
- 显示本次批量预测将使用的标签数量和 prompt。
- 支持选择预测范围：全部任务 / 当前筛选结果 / 未预测任务。
- 批量任务执行后展示结果摘要。

批量预测摘要：

- 成功任务数。
- 失败任务数。
- 总候选框数。
- 平均耗时。
- 失败原因 Top 5。

## 9. 配置数据模型

项目级视觉预标注配置建议结构：

```json
{
  "enabled": true,
  "backend_url": "http://localhost:9092",
  "model": {
    "provider": "grounding_dino",
    "version": "swin_t",
    "device": "auto"
  },
  "prompt": {
    "mode": "from_label_config",
    "manual_prompt": "",
    "joiner": ", "
  },
  "labels": [
    {
      "label": "人员",
      "enabled": true,
      "prompt": "person",
      "aliases": ["people", "human"],
      "unmapped_policy": "discard"
    }
  ],
  "thresholds": {
    "preset": "balanced",
    "box_threshold": 0.3,
    "text_threshold": 0.25
  },
  "prediction_policy": {
    "batch_mode": "empty_only",
    "write_target": "prediction",
    "max_boxes_per_image": 100,
    "max_boxes_per_label": 30
  }
}
```

存储位置：

- 第一选择：项目级设置表，和现有二开设置保持一致。
- 第二选择：ML Backend `/setup` 的 `extra_params`。
- 后端缓存只作为运行时缓存，不作为唯一配置源。

## 10. 后端接口设计

继续兼容 Label Studio ML Backend 标准接口：

- `/health`
- `/setup`
- `/predict`
- `/webhook`

建议扩展内部接口：

- `/metadata`：返回模型版本、设备、权重、支持能力。
- `/preview-prompt`：输入 label config，返回生成的 prompt 和映射表。
- `/test-predict`：输入 task id 和参数，返回预测预览。

这些扩展接口用于二开平台配置页，不影响标准 Label Studio 集成。

## 11. 推理流程

批量预测流程：

```text
用户点击获取预测
  -> Label Studio 调用 /predict
  -> 后端读取项目配置 extra_params
  -> 后端读取 label config
  -> 生成 prompt 和标签映射表
  -> 下载图片到本地
  -> Grounding DINO 推理
  -> 根据 phrase 映射业务标签
  -> 过滤低质量框
  -> 返回 RectangleLabels prediction
```

标注页交互流程：

```text
用户选择标签或输入 prompt
  -> Label Studio 发送 context
  -> 后端优先使用 context prompt
  -> 推理并返回候选框
  -> 标注员确认或修正
  -> webhook 记录接受、删除、修改情况
```

## 12. 质量闭环

需要记录的事件：

- 预测开始。
- 预测成功。
- 预测失败。
- 用户接受预测框。
- 用户删除预测框。
- 用户修改预测框。
- 用户新增人工框。

核心指标：

- 任务级预测成功率。
- 图片平均预测耗时。
- 每图平均候选框数。
- 标签级接受率。
- 标签级删除率。
- 标签级修改率。
- 人工新增框占比，用于估计漏检。

使用方式：

- 删除率高：提高阈值或优化 prompt。
- 人工新增多：降低阈值或增加别名。
- 某标签接受率低：检查标签别名和业务定义是否过宽。

## 13. 权限与安全

权限：

- 只有项目管理员可修改视觉预标注配置。
- 标注员可使用标注页交互式预标注，但不能修改项目默认配置。
- 质检员可查看统计，不一定能改配置。

安全：

- API Token 不在前端明文展示。
- 后端服务建议启用 Basic Auth 或内网访问控制。
- 日志中不得输出完整 Token。
- 图片缓存按项目隔离，支持定期清理。

## 14. 部署与运维

部署形态：

- 独立 Docker Compose。
- 生产环境建议独立 GPU 节点。
- Label Studio 通过服务地址访问。

运维指标：

- 服务健康状态。
- 模型加载状态。
- GPU 显存占用。
- 请求数。
- 平均推理耗时。
- P95 推理耗时。
- 失败率。

运维建议：

- GPU 模式默认 `WORKERS=1`。
- 批量预测走队列或限流，避免阻塞交互式预测。
- 权重下载放在镜像构建阶段，避免运行时冷启动。
- 大项目批量预测需要任务级重试。

## 15. 版本规划

### V1：完整可配置版本

## 16. 验收标准

功能验收：

- 管理员可以在 UI 中启用视觉预标注。
- 系统能从 `RectangleLabels` 自动生成 prompt。
- 系统能把预测结果映射回正确业务标签。
- 批量获取预测可正常写入预测结果。
- 标注页交互式预标注可正常返回候选框。
- 服务连接失败、图片拉取失败、模型失败都有明确提示。

体验验收：

- 管理员无需阅读代码即可完成配置。
- 标注员无需理解 Grounding DINO 参数即可使用。
- 质检员能判断预标注是否值得继续启用。

工程验收：

- 后端可独立构建和部署。
- 配置不依赖容器内临时缓存。
- 日志能定位主要失败原因。
- GPU 并发和模型加载策略清晰。

## 17. 关键风险

- 中文业务标签无法直接作为 Grounding DINO 高质量 prompt，需要别名或翻译。
- 开放词表检测对 prompt 非常敏感，标签定义过宽会导致误检。
- 大图和批量任务会带来明显 GPU 压力。
- 如果未建立质量统计，管理员很难判断阈值是否合理。
- 如果预测结果直接自动提交为标注，可能污染标注数据，默认应只写入预测。
