# Label Studio 无界集成方案梳理

## 一、整体目标（一句话）

在主平台里用无界嵌入 Label Studio 子应用，用户只登录主平台，子应用用主平台 token 访问 LS 接口，不换签、不单独登录 LS。

---

## 二、两种部署方式（二选一）

### 方式 A：首屏直连 LS，后续 API 走网关（当前已实现、推荐）

| 步骤 | 谁发起 | 请求发到哪 | 鉴权 |
|------|--------|------------|------|
| 1. 无界加载子应用 | 主平台/无界 | **直接** `http://LS地址:8080/embed/` | 无，免登录壳 |
| 2. 子应用内 API 请求 | 前端 JS | **网关** `https://主平台/label-studio/api/...`，Header 带 `Authorization: Bearer <主平台token>` | 网关 + LS 主平台 Token 认证 |

- **首屏**：不经过网关，无鉴权问题，无跨域（若主平台 iframe 的 src 是 LS 的地址，请求是浏览器→LS，同域与否看主平台页面的域和 LS 的域是否一致，见下）。
- **后续请求**：`APP_SETTINGS.hostname` 配成网关地址，所有 API 发到网关，由网关转发到 LS。
- **配置**：LS 部署时设置 `EMBED_GATEWAY_HOSTNAME=https://主平台域名/label-studio`，这样 /embed/ 吐出的 HTML 里 hostname 已是网关，前端自然走网关。

### 方式 B：全部走网关（首屏也经网关）

| 步骤 | 谁发起 | 请求发到哪 | 鉴权 |
|------|--------|------------|------|
| 1. 无界加载子应用 | 主平台/无界 | **网关** `https://主平台/label-studio/embed/` | 网关需放行或带主平台 token |
| 2. 子应用内 API | 前端 JS | **网关** `https://主平台/label-studio/api/...` | 同上 |

- 要求：网关对 `/label-studio/embed/` 能放行（或主应用在请求时带上主平台 token），否则首屏就被网关 401。

---

## 三、数据流（方式 A，推荐）

```
用户打开主平台页面（已登录，主平台有 token）
    ↓
主平台用无界加载子应用 URL = http://LS的IP:8080/embed/
    ↓
浏览器请求 LS:8080/embed/  →  LS 返回 HTML 壳（免登录，APP_SETTINGS.hostname=网关地址）
    ↓
页面内 JS/CSS 从 LS:8080 或网关 按 hostname 加载（见下「跨域」）
    ↓
React 启动，getUser() 从无界拿到主平台 token
    ↓
之后所有 API 请求 → 发到 APP_SETTINGS.hostname（网关）→ 网关转发到 LS:8080，Header 带 Bearer token
    ↓
LS 主平台 Token 认证类校验 token，映射用户，返回数据
```

---

## 四、跨域说明（重要）

### 4.1 什么时候会跨域？

浏览器按「页面所在源（origin）」和「请求目标源」判断是否同源。  
无界子应用里「页面所在源」= **子应用文档的 origin**，即你打开的 URL 的 origin：

- **方式 A、首屏直连 LS**：无界 iframe 的 src = `http://LS地址:8080/embed/`  
  → 子应用文档的 origin = `http://LS地址:8080`  
  → 若 API 请求发到 `https://主平台域名/label-studio`（网关），则 **协议/域名/端口任一不同 = 跨域**。
- **方式 B、首屏也走网关**：iframe src = `https://主平台域名/label-studio/embed/`  
  → 子应用文档的 origin = `https://主平台域名`  
  → API 也发到 `https://主平台域名/label-studio` → **同源，不跨域**。

所以：**方式 A 下「首屏直连 LS、API 走网关」通常会产生跨域（子应用在 LS 域，请求发到主平台域）；方式 B 下全部走网关则通常同源。**

### 4.2 跨域时谁要配 CORS？

- **谁响应请求，谁就要允许「请求来源」的 origin。**
- 方式 A：  
  - API 请求发到 **网关**（主平台域名），再由网关转发到 LS。  
  - 浏览器看到的响应来自 **网关**（或网关代理后的响应头由网关返回），因此 **网关** 需要为子应用所在 origin（如 `http://LS地址:8080`）返回 `Access-Control-Allow-Origin` 等 CORS 头；若网关做反向代理且「透传」后端响应，则网关在代理层加 CORS 头即可，LS 可不单独开 CORS。
- 若某些请求在方式 A 下直接打到 **LS:8080**（例如静态资源仍从 LS 拉），则 **LS** 需对主平台或 LS 的 origin 配 CORS（当前项目默认 `CORS_ALLOW_ALL_ORIGINS = True`，生产可改为白名单）。

### 4.3 如何尽量减少/避免跨域？

| 做法 | 说明 |
|------|------|
| **全部走网关（方式 B）** | 子应用入口和 API 都是 `https://主平台/label-studio/...`，子应用文档与请求同源，**无跨域**。需要网关对 /embed/ 首屏能放行。 |
| **首屏直连 + 静态也走 LS，仅 API 走网关（方式 A）** | 子应用在 LS 域，API 在主平台域，会跨域，需**网关（或 LS）** 对 `http://LS地址:8080` 配 CORS。 |
| **同域部署** | 主平台与 LS 同一域名（例如都用主平台域名，LS 通过网关 + 路径前缀暴露），则无界用 `https://主平台/label-studio/embed/`，全部同源。 |

建议：若希望**完全不碰跨域**，优先用 **方式 B（全部经网关）** 或 **同域部署**；若必须首屏直连 LS，则接受「API 跨域」并在**网关注 CORS**（对子应用 origin 放行）。

## 五、各端要做的事（清单）

### 5.1 主平台（无界主应用）

- 无界加载子应用时传入 `props.getUser`，返回 `{ token: 主平台token, ... }`。
- 子应用入口 URL：
  - 方式 A：`http://LS的IP或域名:8080/embed/`
  - 方式 B：`https://主平台域名/label-studio/embed/`

### 5.2 Label Studio 前端（已实现）

- 请求拦截器里从 `window.$wujie?.props?.getUser()` 取 token，给请求加上 `Authorization: <token>`（无 Bearer 前缀，与网关约定一致）。
- `/embed/` 下或 无界环境下收到 401 不跳登录（已按路径/无界判断）。
- `APP_SETTINGS.hostname` 由后端在 /embed/ 的 HTML 里注入为网关地址（方式 A 配 `EMBED_GATEWAY_HOSTNAME`）。

### 5.3 网关

- 路由：例如 `/api/label-studio/**` → Nacos 服务名（LS）。若网关转发时保留完整 path，LS 会通过 RewriteGatewayPath 中间件将 `/api/label-studio/xxx` 重写为 `/api/xxx` 以匹配路由。
- **鉴权与用户信息**：网关校验前端传来的 token 后，将**用户信息 JSON 做 Base64 编码**放入请求头 **`jwt-user`** 再转发给 LS；LS 后端会解析该头并映射到本地用户（无需 LS 再调主平台接口）。
- **跨域**：若子应用 origin 与主平台不同（方式 A），在网关注 CORS，允许子应用所在 origin。若网关已添加 CORS 头，需在 LS 侧设置 **`CORS_DISABLED=true`**，否则响应会带重复的 `Access-Control-Allow-Origin` 导致浏览器报错。

### 5.4 Label Studio 后端（已实现）

- 提供免登录入口 `/embed` 及子路径（`/embed/projects`、`/embed/organization` 等），均返回同一壳，路由由前端处理。嵌入时 LS 不显示 Menubar/侧边栏，仅主内容，导航由主应用控制。
- **jwt-user 认证**：请求头带 `jwt-user`（Base64(用户信息 JSON)）时优先认证，解析后映射 LS 用户。JSON 需含用户标识，支持：`id`/`userId`/`user_id`/`sub`、`email`/`username`/`userName`；可选 `first_name`/`last_name`。若无 email/username，可用 `userId` 作为标识。
- 主平台 Bearer 认证（可选）：`MAIN_PLATFORM_AUTH_ENABLED=1`、`MAIN_PLATFORM_AUTH_USER_URL=...`，LS 自己调主平台接口校验 token。

## 六、配置小结（LS 侧）

| 环境变量 | 说明 |
|----------|------|
| `EMBED_GATEWAY_HOSTNAME` | **完整 API base**，与网关 path 一致，如 `http://172.16.25.137:9000/api/label-studio`。前端会据此发请求到网关。 |
| `CORS_DISABLED` | 当网关已添加 CORS 头时设为 `true`，避免响应中出现重复的 `Access-Control-Allow-Origin`。 |
| 网关请求头 `jwt-user` | 网关将用户信息 Base64 后放入此头，LS 解析并映射用户。 |
| `MAIN_PLATFORM_AUTH_ENABLED` | 可选；是否启用主平台 Bearer 认证（LS 自己调主平台接口）。 |
| `MAIN_PLATFORM_AUTH_USER_URL` | 可选；主平台「用 Bearer token 查当前用户」的接口。 |

---

## 七、总结

- **方案**：无界子应用用主平台 token 访问 LS，不换签；首屏可直连 LS（/embed/）或经网关，API 建议统一走网关。
- **跨域**：首屏直连 LS 且 API 走网关时，子应用与网关不同源，会跨域，需在**网关**（或代理层）为子应用 origin 配置 CORS；若全部走网关或同域部署，则无跨域问题。
- **已实现**：/embed/ 免登录壳、前端带主平台 token、401 不跳登录、LS 主平台 Token 认证类；**你这边需做**：主平台传 `getUser`、网关路由与 CORS、LS 环境变量与主平台用户接口。
