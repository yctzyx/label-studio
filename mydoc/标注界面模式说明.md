# 标注界面模式说明

> 适用范围：Label Studio 二开版本（含任务工作流 task_workflow）  
> 最后更新：2026-05-19

---

## 一、模式总览

系统共有 **5 种编辑器底部按钮模式**，由 2 个维度交叉决定：

| # | 模式名称 | 触发条件 | 底部按钮 | 典型入口 |
|---|---------|---------|---------|---------|
| 1 | 标注提交模式 | 新标注（无 pk），有 `submit` 接口 | **提交** | Label Stream 首次标注 |
| 2 | 标注更新模式 | 已有标注（有 pk），有 `update` 接口 | **更新** | Explorer 打开已有标注 |
| 3 | 审核模式 | `workflow.stage=review/accept` 且当前用户是 `current_assignee` | **驳回 + 通过** | "我的任务-审核员"入口 |
| 4 | Quick View 审核 | Explorer 中打开他人已提交标注，且 `canBeReviewed=true` | **驳回 + 通过** | Data Manager 点开他人标注 |
| 5 | 只读模式 | `workflow.stage=done` 或非责任人查看 | 无操作按钮 | 已完成任务回看 |

## 二、入口与模式的对应关系

### 2.1 Data Manager（Explorer 模式）

- **入口路径**：`/projects/:id/data`，点击任务列表中某条任务
- **DataManager mode**：`explorer`
- **特征**：
  - 可浏览项目全量任务
  - 支持新增标注、查看全部标注、删除标注、切换标注 Tab
  - 无"上一条/下一条"流式导航，无"跳过"按钮
  - 提交后停留在当前任务
- **底部按钮**：
  - 若 workflow 开启且当前用户是 `current_assignee`：按 stage 切换为"提交/更新"或"驳回/通过"
  - 若非当前责任人：仅显示"更新"（review 接口不开启）
  - 若无 workflow：按标注是否已存在切换"提交"或"更新"

### 2.2 Label Stream（流式标注模式）

- **入口路径**：`/projects/:id/data?labeling=1`，或点击项目卡片的"Label"按钮
- **DataManager mode**：`labelstream`
- **特征**：
  - 系统自动分配下一条任务
  - 有"上一条/下一条"导航（`topbar:prevnext`）
  - 可配置"跳过"按钮（`skip`）
  - 无标注管理功能（不可新增、删除、查看全部标注）
  - 提交后自动加载下一条（`loadNextTask()`）
- **底部按钮**：
  - "提交"（首次）或"更新"（已有标注）
  - 若配置了审核评论要求：附加评论提交逻辑
  - 若开启 workflow 且 stage 匹配审核阶段：切换为"驳回/通过"

### 2.3 我的任务（二开待办队列）

- **入口路径**：`/my-tasks` → 点击"开始标注/去审核/去验收"
- **跳转目标**：`/projects/:id/data?task=:taskId`（实际走 Explorer 模式）
- **特征**：
  - 列表已按 `workflow.stage + current_assignee_id = 当前用户` 严格过滤
  - 用户只能看到自己负责的任务
  - 进入编辑器后 workflow 判定一定命中"当前用户是责任人"
- **底部按钮**：
  - 标注员 Tab：提交/更新
  - 审核员 Tab：驳回 + 通过
  - 验收员 Tab：驳回 + 通过

## 三、模式切换的判定逻辑

编辑器加载任务时，按以下顺序判定底部按钮模式：

```
setLSFTask(task)
  └─ applyWorkflowEditorMode(task)
       ├─ 1. 从 task 快照或 GET /api/tasks/:id/workflow/ 获取 workflow
       ├─ 2. 解析 workflow.stage 和 workflow.current_assignee_id
       ├─ 3. 获取当前用户 ID（lsf.user.id / APP_SETTINGS.user.id）
       └─ 4. 调用 applyWorkflowEditorInterfaces(lsf, workflow, currentUserId)
            ├─ stage=done         → 关闭所有操作按钮（只读）
            ├─ isAssignee + review/accept → 开启 review 接口（驳回/通过）
            ├─ isAssignee + annotate      → 开启 submit/update 接口（提交/更新）
            └─ 其他（非责任人/无 workflow）→ 关闭 review 接口（退化为更新）
```

关键代码位置：`web/libs/datamanager/src/sdk/lsf-sdk.js` 的 `applyWorkflowEditorInterfaces()` 函数。

## 四、底部按钮组件的渲染逻辑

底部按钮由 `web/libs/editor/src/components/BottomBar/Controls.tsx` 渲染，核心判定：

```
isReview = store.hasInterface("review") || annotation.canBeReviewed
```

- `isReview = true`：渲染 **驳回** + **通过** 按钮
- `isReview = false` 且 `annotation.skipped`：渲染 **已跳过** + **撤销跳过**
- `isReview = false`：
  - 有 `skip` 接口：渲染 **跳过** 按钮
  - 新标注（`userGenerate` 且未发送）：渲染 **提交** 按钮
  - 已有标注：渲染 **更新** 按钮

## 五、各模式的提交后行为

| 模式 | 操作 | 提交后行为 |
|------|------|-----------|
| Explorer + 标注 | 提交/更新 | 停留在当前任务；若开启 workflow 则调用 `maybeAdvanceTaskWorkflowAfterLabeling` 推进到 review |
| Label Stream + 标注 | 提交 | 自动加载下一条任务；若开启 workflow 则同步推进 |
| 审核模式 | 通过 | 调用 `maybeAdvanceTaskWorkflowAfterReviewDecision(approve=true)` → 流转至 accept 或 done；reload 当前任务或加载下一条 |
| 审核模式 | 驳回 | 调用 `maybeAdvanceTaskWorkflowAfterReviewDecision(approve=false)` → 退回 annotate 阶段；reload |
| 验收模式 | 通过 | 同审核通过，但直接进入 done |
| 验收模式 | 驳回 | 同审核驳回，退回 annotate 阶段 |

## 六、接口开关（interface）速查

| 接口名 | Label Stream | Explorer | 审核/验收模式 |
|--------|:-----------:|:-------:|:-----------:|
| `submit` | ✅ | ✅ | ❌ |
| `update` | ✅ | ✅ | ❌ |
| `review` | ❌ | ❌ | ✅ |
| `skip` | 可配置 | ❌ | ❌ |
| `topbar:prevnext` | ✅ | ❌ | ❌ |
| `annotations:add-new` | ❌ | ✅ | ✅ |
| `annotations:view-all` | ❌ | ✅ | ✅ |
| `annotations:delete` | ❌ | ✅ | ✅ |
| `ground-truth` | ❌ | ✅ | ✅ |

> 注：审核/验收模式下 `submit` 和 `update` 被关闭，`review` 被开启，以显示"驳回/通过"按钮。
